# URL Shortener Service

A single-process, dependency-free URL shortener with a REST API, pluggable persistence
(in-memory or SQLite), click analytics, and built-in rate limiting — structured so each
layer can scale out independently. Generated by the Agentic SDLC system.

## Run it

```bash
python -m url_shortener.server        # serves on http://127.0.0.1:8000 (in-memory store)
SHORTENER_STORE=sqlite SHORTENER_DB_PATH=shortener.db python -m url_shortener.server   # durable
```

Environment: `SHORTENER_HOST`, `SHORTENER_PORT`, `SHORTENER_BASE_URL`, `SHORTENER_STORE`
(`memory` | `sqlite`), `SHORTENER_DB_PATH`.

Rate limiting environment: `SHORTENER_RATE_LIMIT` (requests per window, default `60`),
`SHORTENER_RATE_LIMIT_WINDOW_SECONDS` (default `60`), `SHORTENER_RATE_LIMIT_ALLOWLIST`
(comma-separated list of client keys, e.g. `ip:10.0.0.1,key:internal-token`, that bypass
the limit entirely — handy for trusted callers or internal testing).

## Try it

```bash
curl -X POST http://127.0.0.1:8000/api/shorten \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com/some/long/path"}'
# -> {"code": "...", "short_url": "http://.../<code>", ...}

curl -i http://127.0.0.1:8000/<code>          # 302 redirect
curl http://127.0.0.1:8000/api/stats/<code>   # click analytics
```

## Rate limiting

Every request (except `/healthz`, `/metrics`, and `/admin/*`) is checked against a
per-client fixed-window counter, identified by API key (`Authorization` or
`X-API-Key` header) when present, otherwise by remote IP address. All responses
carry `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset` headers;
requests over the limit get `HTTP 429` with the same headers.

```bash
curl http://127.0.0.1:8000/metrics                       # total/blocked request counts
curl http://127.0.0.1:8000/admin/rate-limit-config        # current limit/window/allowlist
curl -X PUT http://127.0.0.1:8000/admin/rate-limit-config \
  -d '{"limit": 100, "window_seconds": 60}'               # reconfigure without redeploy
curl -X POST http://127.0.0.1:8000/admin/rate-limit-reset \
  -d '{"key": "ip:127.0.0.1"}'                             # reset one client (omit key for all)
```

The counter store lives behind a small `RateLimitStore` interface (see
`url_shortener/ratelimit.py`) so an in-memory implementation (default, single
instance) can later be swapped for a shared backend like Redis to keep limits
consistent across horizontally-scaled instances, without changing the limiter API.

## Test it

```bash
python -m unittest discover -s tests -v
```

## Layout

| Path | Responsibility |
| --- | --- |
| `url_shortener/base62.py` | id <-> slug codec |
| `url_shortener/store.py` | in-memory + SQLite backends |
| `url_shortener/service.py` | validation, shorten, resolve, stats |
| `url_shortener/analytics.py` | click aggregation |
| `url_shortener/ratelimit.py` | fixed-window rate limiter, metrics, config |
| `url_shortener/api.py` | WSGI HTTP adapter |
| `url_shortener/server.py` | dev server entrypoint |
| `openapi.yaml` | API contract |
